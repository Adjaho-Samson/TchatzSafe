# Audit de TchatzSafe — 1er novembre 2026

## Périmètre et état initial

Le dépôt est un site statique HTML/CSS/JavaScript, généré depuis `templates/pages/` et `tools/build-pages.py` puis déployable sur Vercel. Il comporte 14 pages, six fiches de menaces, 17 formations et 20 quiz. Les routes et identifiants historiques sont conservés. Les polices et les images sont locales ; l’interface comprend un thème clair, un thème sombre et un menu mobile.

La progression, les préférences et les brouillons sont conservés sur l’appareil dans `localStorage`, sans compte ni synchronisation. L’import/export de progression existe. Les leçons peuvent être marquées comme étudiées et les quiz enregistrent leur dernier résultat et leur meilleur score. En revanche, la position à l’intérieur d’une formation et un historique lisible des formations ne sont pas mémorisés.

L’analyseur applique des règles syntaxiques locales et ne détermine ni la réputation ni la sécurité d’une ressource. Le formulaire de signalement ne transmet rien : il crée, avec accord, un brouillon local. La page de modération est un atelier local non authentifié, pas une administration. Ces limites doivent rester visibles.

## Défauts et risques relevés avant intervention

- Les 14 HTML versionnés contiennent une balise Google Analytics ajoutée hors du générateur : la CSP bloque le script distant et le script inline. Cela produit des erreurs de console, fait échouer `npm run check` et contredit la politique de confidentialité. La régénération ne conserverait pas ces balises.
- Pas de manifest, de service worker, de cache hors connexion, d’installation ni de gestion des mises à jour.
- Pas de statistiques fonctionnelles vérifiables ni d’espace de statistiques privé dans le projet. Un accès public à des données administratives ou des valeurs fictives serait inacceptable.
- Les leçons n’enregistrent que leur statut « étudiée » ; aucun chapitre de reprise n’est enregistré. La page de progression ne présente pas de liste des formations étudiées.
- Les icônes proviennent d’un sprite SVG dessiné pour le projet, pas de Font Awesome. Certaines tailles de texte et certains espacements sont très réduits sur mobile.
- Les espaces contenant « Chargement… » dépendent de JavaScript : une panne de script doit produire un état d’erreur plutôt qu’un chargement interminable.
- Les mentions de confidentialité ne peuvent pas rester inchangées si une mesure d’audience est ajoutée. Une solution de suivi doit minimiser les données, informer les visiteurs, respecter leur choix et ne pas transmettre les contenus de formulaires.
- La CSP bloque toutes les connexions (`connect-src 'none'`) ; une mesure Vercel nécessite une modification limitée et cohérente dans le HTML et les en-têtes. Le serveur local ne fournit pas les routes Vercel.

## Vérifications initiales réellement exécutées

- `npm ci` : installation des outils réussie, aucun incident signalé.
- `npm test` : 36 tests unitaires réussis.
- `npm run check` : échec sur les 14 scripts inline non autorisés.
- Chargement de l’accueil dans Chromium 153 : deux violations de CSP observées pour les balises Google Analytics.
- Le navigateur Playwright prévu par défaut n’est pas téléchargeable depuis son CDN dans cet environnement ; un Chromium provenant d’un paquet npm est utilisé pour les vérifications navigateur locales ultérieures.

## Principes de correction

Conserver les clés de stockage et les identifiants existants ; ajouter les champs de reprise de manière rétrocompatible. Ne pas transformer l’analyseur ou les brouillons en services connectés fictifs. Utiliser Vercel Web Analytics uniquement après accord, sans paramètres d’URL ni contenu de formulaire, et réserver la consultation des données au tableau de bord Vercel authentifié. Documenter explicitement les étapes d’activation et les limites non testables sans accès au projet Vercel.
